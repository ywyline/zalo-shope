## 2. 目标与非目标

目标：

- `POST /v1/after-sales/{afterSaleId}/return-shipment` 在排他截止点前原子创建唯一 `SUBMITTED` 返件，
  只追加 `START_RETURN`，把 `APPROVED` 推进到 `RETURN_PENDING`。
- 买家承运商/运单号只作为未验证声明；运单号只保存 keyed HMAC 摘要和掩码，不进入日志、审计、
  operation 结果或公开错误。
- `POST /v1/admin/after-sales/{afterSaleId}/return-shipment/fact` 只接受 `IN_TRANSIT` 或 `DELIVERED`
  可信人工核验事实。`IN_TRANSIT` 追加 `RETURN_SHIPPED`；`DELIVERED` 根据当前状态追加
  `RETURN_RECEIVED`，必要时同事务先补 `RETURN_SHIPPED`。
- 可信事实核验可以发生在会员已按时登记之后，不再错误受会员登记截止点限制。
- 两条命令都返回不可变 acknowledgement，并具备商城/主体写限流、幂等、expected version、
  correlation ID、审计和最终提交前授权重验。
- B1 管理员列表使用 `status=INSPECTION_PENDING`、详情中的返件状态和时间线构成待验收读取；B5 不新增
  宽投影或验收写接口。

非目标：

- 不把会员填写的承运商、运单号或提交动作当作 `IN_TRANSIT/DELIVERED` 供应商事实。
- 不开放 `REJECTED/UNKNOWN` 管理命令；异常状态缺少冻结聚合语义时继续失败关闭。
- 不创建 `after_sale_inspections`、库存 movement/reservation、M5 refund、settlement、物流 provider
  outbox 或 `shipments` 事实。
- 不保存可恢复的明文运单号，不调用 GHN/GHTK 等外部接口，不声称真实物流集成可用。
- 不启用 production，不新增生产角色授权，不声称越南业务或合规就绪。

## 5. 事务、兼容与回滚

- 两条命令使用 `Serializable`：幂等 advisory lock -> 订单 advisory lock -> 订单 -> 售后 header ->
  返件 -> operation/transition/audit。仅 `P2034`/SQLSTATE `40001` 最多重试三次；显式 expected-version
  冲突不重试。
- 会员登记先写 `SUBMITTED`，再追加 `START_RETURN`；B0 deferred guard 与 B5 operation/transition/audit
  deferred guard 共同拒绝部分提交。
- 管理员事实先锁返件与售后聚合，更新可信状态后追加一条或两条 transition；结果 summary 冻结最终
  aggregate/返件状态和双版本。
- 最终 SQL 函数在所有可能等待的锁后重验 ACTIVE 商城、主体/session/token；管理员额外重验近期 MFA
  和目标商城直接 review 权限。
- B5 只新增前向迁移。`down.sql` 仅允许没有 B5 operation、返件可信状态、B5 transition/audit 的
  local/test；存在事实时以 SQLSTATE `55000` 拒绝。production 和已有 B5 事实环境只允许向前修复。
- 应用回滚为保持新开关 false；已有返件、transition、audit 和 operation 不删除、不逆转。

## 6. 风险与停止条件

- 明文运单号进入数据库、日志、审计、错误或响应，必须停止并失败关闭。
- 会员命令能写 `IN_TRANSIT/DELIVERED`、管理员能记录未冻结状态，或没有可信权限/MFA/原因即推进，
  必须拒绝。
- 截止 worker、会员登记、管理员事实使用不同聚合锁序，或并发时能产生孤立返件/重复 transition，
  必须停止。
- 管理员事实能触发验收、库存、换货、退款、COD 或外部物流副作用，必须停止并拆回后续阶段。
- 真实 provider、生产政策、凭据、部署和 rollout 未获批准；local/test 通过不能改变该状态。
