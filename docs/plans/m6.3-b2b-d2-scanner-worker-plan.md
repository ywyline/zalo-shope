## 2. 目标与非目标

### 2.1 目标

- 新增独立 `AfterSaleEvidenceScanner` contract 和真实 ClamAV `INSTREAM` adapter；只把 ClamAV 精确
  `stream: OK` 解释为 `CLEAN`，严格解析 `VERSION`、拒绝过期/未来签名库，并保存
  engine/version/signature identity。
- scanner 使用 server-only、默认 `disabled` 的 host/port/timeout/response-limit 配置；local/test 使用
  固定版本官方 ClamAV 容器，不提供固定返回 `CLEAN` 的测试 provider。
- D1 storage adapter 增加受控 consumer 入口：独立 read 身份先做 HEAD 初筛并取得非空 ETag，GET
  必须用 `If-Match` 绑定该对象版本，再用同一条有界流复算实际长度、SHA-256 和 magic，同时把经过
  边界检查的字节交给 scanner。只有完整消费、内容校验与 scanner 响应都成功，结果才可投影。
- 新增 scan-work loader 与 lease-bound scan-result 原语。外部调用前后都校验 scan outbox；结果提交
  必须在同一事务使用数据库 `clock_timestamp()` 复核 `PROCESSING`、lease owner、未过期 lease、
  message version、商城、严格 payload、evidence version/generation/status，再投影结果并可靠排队 expire。
- worker 严格解析消息，使用 `createAfterSaleEvidenceSystemContext` 的固定 actor/scope，不冒用管理员或
  普通 `StoreContext`。配置完整的 storage 与 scanner 才能注册真实 scan handler。
- 新增持久且有界的 scan dead-letter 候选轮询与收敛服务；通用 outbox 不会重新领取 `DEAD_LETTER`，
  因此不能只注册 handler 而让异常崩溃/lease exhaustion 后的 evidence 永久停在 `PENDING`。
- 覆盖干净、恶意、超时、不可用、协议异常、对象校验失败、重复/乱序、跨商城及租约丢失。

### 2.2 非目标

- 不修改 OpenAPI operation runtime status，不把内部 worker 称为会员可用的上传/扫描能力。
- 不新增 scanner 临时对象、衍生物、隔离 bucket 搬移、内容审核、图片解码或视频转码。
- 不消费 expire/delete outbox，不物理删除对象，不解决 VersionId/Object Lock 或生产 lifecycle。
- 不批准生产 claim/failed-retention TTL、scanner SLA、网络边界、签名库更新策略、告警接收方或容量。
- 不调用 Zalo、支付、物流或其他供应商，不部署、不发布、不推送。

## 3. 冻结接口与状态语义

### 3.1 Scanner contract

scanner 只接收 `AsyncIterable<Uint8Array> + expectedByteSize`，流式发送 ClamAV `zINSTREAM\0` 帧；
单帧固定不超过 64 KiB，实际总字节必须精确等于 expectedByteSize 且不得超过 P0 视频上限 50 MiB。
连接、总操作和响应均有界，响应必须为单个 NUL 终止帧且不超过配置上限。

VERSION 与实际扫描必须在同一个 `zIDSESSION\0` 连接完成：严格读取 request id 1 的 `zVERSION\0`
响应，再发送 request id 2 的 `zINSTREAM\0`，最后以 `zEND\0` 结束。响应 id、顺序、NUL 帧或尾随字节
任一不符即协议错误，不能用另一连接上的 VERSION 观察冒充本次扫描 identity。

`zVERSION\0` 必须严格解析为：

- `engine = clamav`（稳定内部 provider ID；原始 VERSION 产品名必须精确为 `ClamAV`）
- `engineVersion = ClamAV engine version`
- `signatureVersion = virus database numeric version`

VERSION 中的签名库时间必须可严格解析、不超过允许未来时钟偏差，且年龄不大于配置上限；否则按
`SCANNER_PROTOCOL_ERROR` 失败关闭，不能把 engine 可连接等同于签名可用。

扫描结果与失败分类冻结为：

- 精确 `stream: OK` -> `CLEAN`
- 严格 `stream: <signature> FOUND` -> `MALICIOUS`，数据库稳定 code 为 `MALWARE_DETECTED`；签名名不返回、
  不记录、不持久化
- socket timeout -> `SCANNER_TIMEOUT`
- DNS/连接/传输不可用 -> `SCANNER_UNAVAILABLE`
- 超限、非 UTF-8、额外帧、无法解析的 VERSION/scan 响应或 ClamAV ERROR ->
  `SCANNER_PROTOCOL_ERROR`
- D1 metadata/content/length/checksum/magic 失败 -> `OBJECT_VALIDATION_FAILED`

只有 `CLEAN` 可进入 `READY_UNCLAIMED`；`MALICIOUS` 进入 `QUARANTINED`；最终不确定结果进入
`FAILED`。错误对象只暴露稳定 code/retryable，不包含 socket 正文、恶意签名、对象 key、checksum、
签名 URL 或供应商响应。

### 3.2 重试与消息完成

- `SCANNER_TIMEOUT`、`SCANNER_UNAVAILABLE` 及 storage `UPSTREAM_UNAVAILABLE` 在 scan outbox 尚有剩余
  attempt 时交给现有可靠消息框架有界重试。
- 最后一次正常 handler attempt 可将上述稳定 code 作为 `INDETERMINATE` 租约安全投影，确保 evidence
  失败关闭并排队清理；确定的恶意、协议错误和对象内容不匹配不重复调用外部服务。
- handler 成功投影后仍由现有 `ReliableOutboxService` 调用 generic complete。投影后、complete 前崩溃时，
  重领 handler 看到 evidence 已推进后返回 `SUPERSEDED`，再完成旧 scan message，不重复写结果。
- loader 通过后租约可能丢失，因此 result primitive 必须再次校验租约；loader 结果不能作为提交授权。
- handler 未能执行最终投影而由通用框架写成 `DEAD_LETTER` 时，独立 scan reconciler 使用 D0 的严格
  message/evidence 复核把仍待扫描的权威对象收敛为 `FAILED` 并排队 expire；已有更新 scan request 的
  旧死信只返回 `SUPERSEDED`，不得覆盖新 generation。

scan outbox payload 继续精确只有：

```json
{
  "store_id": "...",
  "evidence_id": "...",
  "expected_version": 1
}
```

不得加入 object key、MIME、byte size、checksum、scan generation、scanner identity/result、截止点或错误正文。

### 3.3 配置与注册

新增 `EVIDENCE_SCANNER_*` server-only 配置：provider、host、port、timeout、response limit、签名库最大
年龄、clean claim TTL、failed retention TTL，以及 dead-letter reconcile interval/batch。provider 默认
`disabled`；启用 ClamAV 时所有运行字段必须显式有效，且 `EVIDENCE_STORAGE_PROVIDER=s3`。没有
heartbeat 的当前 worker 还要求 outbox lease 大于 storage/scanner 最坏配置时间预算并保留提交余量，
否则启动失败。

实现收口将 loader/result 两个 lease-bound SERIALIZABLE 事务各限制为 2 秒，预算冻结为
`HEAD + max(GET, scanner) + 2 * 2000ms + 5000ms`；默认 10 秒 storage/scanner 组合要求租约至少
29 秒。两个入口在 evidence 锁等待后都重新读取数据库时钟，不能使用事务开始时的陈旧租约判断。

`.env.test.example` 使用明确的 local/test 24 小时 claim/failed-retention 基线；这些值不是生产政策。
Clamd TCP 没有认证和 TLS；production 配置只接受显式 loopback sidecar 地址，远程明文 scanner host
启动失败。production 的 HTTP storage、缺 KMS 或无法覆盖 timeout 预算时继续失败关闭。D2 不用“配置
可解析”代替目标生产网络、签名更新、容量或 SLA 验收。

- D2 不改 schema、RLS、grant、trigger、枚举或迁移；M2→current 预计继续为 43 段。

- 既有 `applyAfterSaleEvidenceScanResult` 保持 D0 兼容和原有测试；D2 worker 只能调用新增 lease-bound

- 回滚应用时必须先停止新的 scan consumer；已形成 evidence/outbox/transition 事实不能删除。恢复旧代码
  后 scanner 消息会保持待处理或失败关闭，后续必须保留兼容 worker/reconciler 向安全终态收敛。
- local/test 可停止 ClamAV 容器；不自动删除 MinIO bucket、数据库事实或签名库卷。生产及已有凭证事实
  环境只允许受审前向修复。

## 6. 风险、依赖与停止条件

- **旧 worker 越权提交**：只在 lease-bound 事务内投影；错误 owner/version、已到期 lease 或 DB 时钟
  等于截止点均拒绝，generic complete 不能补救已经发生的领域写入。
- **对象替换或 metadata 欺骗**：scanner 只消费 D1 读身份取得的活动 ORIGINAL，同一 GET 流同时执行
  总量、digest 和 magic 校验；provider metadata 不能单独产生 CLEAN。
- **死信永久 PENDING**：持久 scan dead-letter 轮询只处理严格 scan v1 候选；收敛原语重新锁消息与
  evidence，重复运行幂等，旧 generation 不覆盖新事实。
- **协议/正文泄漏**：严格 NUL 帧与响应上限；任何异常只保留稳定 code，不记录 ClamAV signature、
  provider error、对象 key 或 checksum。
- **长扫描超过租约**：配置预算门禁保留提交余量；D2 不实现 heartbeat。若 50 MiB 在目标环境无法在
  预算内稳定完成，停止 production rollout，后续另行设计续租而不是放宽租约校验。
- **关闭时中断在途扫描**：outbox、scan dead-letter 与库存轮询在 `onModuleDestroy` 先停止领取并等待
  当前工作；共享 Prisma 与 S3 client 只在后续 `onApplicationShutdown` 释放。Nest provider 同阶段
  并发销毁不能先截断 scanner 正在消费的对象流。
- **测试病毒样本误用**：EICAR 只在 local/test 运行时由分段字符串构造，不提交二进制恶意样本；真实
  ClamAV 必须识别，不能用 mock CLEAN/MALICIOUS 代替集成证据。
- **生产签名与 SLA 未验收**：官方 local/test 容器只证明协议和仓库协调，不证明生产隔离、签名更新、
  HA、吞吐、监控或响应承诺。

任一精确 CLEAN、EICAR、租约竞争、跨商城隔离、内容复验、错误脱敏或清理无法稳定通过时停止 D2
完成声明。

## 7. 测试与验收

### 7.1 单元与静态

- config 默认 disabled；缺 host/TTL、非法 port/timeout/limit/signature age、storage 未启用、lease 预算
  不足和 production 非 loopback host 均失败关闭且错误不泄密。
- ClamAV 分片写入、大小帧、NUL 响应、VERSION/OK/FOUND、超限、timeout、unavailable、ERROR、额外
  数据和正文脱敏。
- storage consumer 完整消费、提前返回、异常 chunk、超限、checksum/magic/长度错误均中止流并拒绝。
- worker payload 精确键集、aggregate/store/version/lease 绑定、错误分类、最后 attempt 与 handler 注册。

### 7.2 数据库与真实基础设施集成

- 真实 MinIO ORIGINAL 经过同流实际 bytes 校验后送入真实 ClamAV：干净允许格式进入
  `READY_UNCLAIMED`，带 EICAR 的允许格式进入 `QUARANTINED`，且不持久化/记录 signature 正文。
- scanner unavailable/timeout 最后 attempt、协议错误、签名库过期和对象校验失败进入 `FAILED`；非最后
  transient 保持 `PENDING` 并由 outbox 有界重试。
- 有效 lease 绑定投影；错 owner/version/status、空/到期 lease拒绝。A 租约到期由 B 重领后，A 即使
  使用相同 payload 也不能提交；loader 后丢 lease 同样拒绝。
- 重复、乱序、旧 evidence version/generation 返回 `SUPERSEDED`；投影后 complete 前崩溃的重领不重复
  expire message；expire outbox 写失败时结果投影整体回滚。
- 双商城已知 UUID、跨商城 message/evidence、畸形 aggregate/payload 在 scanner 调用前拒绝。
- retry exhaustion、lease-expired exhaustion 和 handler 崩溃形成的 scan dead letter 最终由持久轮询
  收敛为 `FAILED`；重跑不重复 transition/expire，已有新 request 时旧死信不污染当前状态。
