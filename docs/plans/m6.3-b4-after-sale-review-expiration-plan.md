## 1. 授权与范围

用户于 2026-07-31 要求按仓库严谨工作流继续下一阶段。B3 已完成后，批准路线图中唯一相邻且尚未
开始的仓库切片是 B4。本计划授权实现默认关闭的 repository/local-test 管理员初审、legacy 一次性
决定、非 legacy 人工复核恢复/早期拒绝，以及 SYSTEM 寄回截止 worker。

本授权不包含生产政策或开关、真实支付/退款、COD 结算、返件提交或物流事实、验收、库存恢复、换货
履约、UI、部署或发布；这些能力继续失败关闭，且 B4 完成不代表 B2/B2b、M6.3、M6 或 P0 完成。

## 2. 目标与非目标

目标：

- `POST /v1/admin/after-sales/{id}/review` 对非 legacy `PENDING_REVIEW` 原子执行批准或拒绝。
- `POST /v1/admin/after-sales/{id}/resolve-review` 执行一次性 legacy 决定，或按冻结的
  `review_resume_status` 恢复/早期拒绝非 legacy 人工复核。
- 逐行批准仅接受 `approved_quantity`；服务端锁定订单和售后行并按已冻结整数 VND 余数算法重算金额。
- 为退货退款/换货在批准事务中按越南自然日冻结排他 `return_deadline_at`。
- 到点后 SYSTEM worker 幂等追加 `RETURN_EXPIRED`；与后续 B5 返件提交共享聚合锁，竞态至多一个成功。
- 人工写入具备目标商城直接权限、近期 MFA、确认词、原因、expected version、商城+主体写限流、幂等、
  correlation ID、审计和最终提交前授权重验。

非目标：

- 不由审核命令创建 M5 refund、settlement、provider outbox、返件/换货 shipment 或库存动作。
- 不开放 `inspect-return`，不把买家输入当作可信物流/签收事实。
- 不自动为 legacy 订单回填当前政策；`policy_basis` 只保存加密的历史规则引用/摘要。
- 不允许人工任选复核恢复目标；只能恢复数据库冻结的同类型状态。
- 不启用 production，不创建生产角色授权，不声称生产或越南合规就绪。

## 3. 冻结默认值

| 决策            | B4 repository/local-test 默认值                                                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 返回体          | 与 B3 一致返回原 operation 的不可变 acknowledgement；当前聚合由 B1 GET 读取                                                                                  |
| 普通批准        | 请求必须逐行、唯一且完整覆盖；至少一行正数，任一数量不得超过申请量                                                                                           |
| 批准金额        | `approved_item_vnd` 仅由服务端按该申请行 `requested_item_vnd * approved/requested` 向下取整；批准全部申请量取得该行全部申请 VND                              |
| 运费/其他       | 有正数批准时批准既有申请运费/其他额；不得由客户端提交；订单级 allocation 与 header 同事务写入                                                                |
| 退货期限        | 普通 case 读取冻结 `policy_snapshot.return_window_days`；批准日不消耗完整寄回日，使用 `Asia/Ho_Chi_Minh` 排他截止点                                          |
| legacy 批准数量 | 当前冻结 resolve-review 契约没有逐行输入，因此按既有请求行全量批准；客户端仍不能提交金额                                                                     |
| legacy 政策     | 只追加加密 `policy_basis`、规范 payload/hash、管理员和理由；不伪造历史 policy/version                                                                        |
| 商家主动退款    | 创建管理员不得审核自己发起的 `MERCHANT_REFUND`；必须由目标商城另一个具备 review 权限且近期 MFA 的管理员决定                                                  |
| 人工复核        | `RESUME` 只能回到 `review_resume_status`；`REJECT` 仅限冻结状态为 `APPROVED/RETURN_PENDING` 且事务证明无资金、返件、验收、库存、换货或非订单 shipment 副作用 |
| 到期 worker     | 独立 `AFTER_SALE_RETURN_EXPIRATION_WORKER_ENABLED=false`；production 配置拒绝启用，批次和间隔有界                                                            |
| 能力开关        | 人工审核使用独立 `AFTER_SALE_REVIEW_COMMANDS_ENABLED=false`；不借 B3 开关隐式开放                                                                            |

## 5. 事务、兼容与回滚

- 管理员命令使用 `Serializable`：幂等锁 -> 订单 advisory lock -> 订单 -> 售后 header -> 售后/订单行 ->
  容量/副作用事实 -> approval/legacy/operation/transition/audit。仅 `P2034`/SQLSTATE `40001` 最多重试
  三次；明确 expected-version 冲突不重试。
- operation 以商城、operation 和幂等 key hash 唯一；同键同规范请求返回原 result，异参稳定 `409`。
- 最终 SQL 函数在提交前重验 ACTIVE 商城、管理员/会话/token、近期 MFA、目标商城直接
  `store.after-sales.review`；cross-access-only 继续 `403`。
- B4 只新增前向迁移。`down.sql` 仅限无 B4 operation/transition/audit 的 local/test；存在事实以
  SQLSTATE `55000` 拒绝。生产和已有 B4 事实环境只允许向前修复。
- 应用回滚为保持两个新开关 false；已有审核和到期事实不删除、不逆转。

## 6. 风险与停止条件

- 任何客户端金额进入写路径、整数余数不一致、逐行漏项/重复、订单级 allocation 重复或累计权益超限，
  必须停止并失败关闭。
- legacy 决定被当前政策替代、能执行两次、非退货类型接受返件条款，或同管理员自批商家退款，必须拒绝。
- 审核、取消、后续返件和到期锁序不一致或能同时成功，必须停止。
- SYSTEM 身份缺少专用 scope、能执行人工事件或审计冒用管理员，必须停止。
- 外部生产政策、凭据、对象存储、供应商或 rollout 未获批准；本地通过不能改变该状态。
