## 2. 目标与非目标

### 2.1 目标

- 新增专用 `AfterSaleEvidenceObjectStorageProvider`，不复用 `MediaStorageProvider` token、bucket 或
  对象 key。
- 上传目标固定 create-only，并绑定服务端生成的规范 evidence key、Content-Length、Content-Type 和
  SHA-256 checksum；四项上传约束均进入签名，checksum header 不得提升到 query，客户端不能选择或覆盖 key。
- 校验入口以专用读取凭据执行 HEAD 与有界流式 GET，重新计算实际字节数和 SHA-256，并校验
  JPEG/PNG/WebP/MP4 magic；只返回稳定的安全分类，不返回对象 key、签名 URL 或供应商正文。
- 删除入口使用独立 delete-only 凭据；S3 成功与明确 `NoSuchKey + 404` 按幂等已删除语义处理，
  `NoSuchBucket`、普通 `404`、未知错误或超时不能当作成功。
- 保护读取签名能力只存在于内部 adapter，强制短 TTL 与 `private, no-store` response override；D1
  不提供会员/管理员调用方，也不宣称管理员读取审计已完成。
- 配置默认 `disabled`。启用 S3 evidence provider 时必须提供独立 bucket、上传/读取/删除三组凭据、
  有界超时和 URL TTL；与 catalog/content bucket 或 access key 复用时启动失败。
- bucket 名必须满足受支持的 DNS 形状，拒绝相邻点、IP 地址形式和其他不稳定/歧义名称。
- 本地/测试 MinIO 由 root bootstrap 身份创建 content/evidence 独立 bucket、content 用户和三组
  evidence 最小用户；应用测试不得使用 root 身份。

### 2.2 非目标

- 不修改 Prisma schema、D0 迁移、RLS、transition 或 outbox 协议。
- 不把 provider metadata 中的 Content-Type 或 checksum 单独当作可信内容；最终判断必须读取实际
  bytes。
- 不做图片解码、视频转码、内容审核或恶意文件扫描；magic 通过不等于安全 CLEAN。
- 不配置或批准生产 KMS key、bucket lifecycle、Object Lock、跨区域复制、告警接收方或 retention。
- 不允许普通 catalog/content provider 访问 evidence bucket，也不让 evidence provider 访问 content
  bucket。

## 3. 接口与配置冻结

### 3.1 Provider contract

内部 provider 至少提供：

- `createUploadTarget`：接收规范对象身份、声明 MIME/长度/checksum，返回短期签名 PUT 目标和必须原样
  发送的 headers。
- `validateUploadedObject`：接收同一规范身份与声明元数据，执行 HEAD + 有界流式 GET，成功只返回
  规范 MIME、长度、checksum 和 magic 类型。
- `createProtectedReadTarget`：生成短期 GET，响应强制 `private, no-store`；没有 D1 HTTP 调用方。
- `removeObject`：delete-only 客户端执行幂等删除；不在错误中暴露 key 或供应商响应。

稳定错误分类冻结为 `CONFIGURATION/INVALID_IDENTITY/NOT_FOUND/METADATA_MISMATCH/
CONTENT_MISMATCH/UPSTREAM_UNAVAILABLE`。调用方只能依据分类失败关闭，不能解析供应商正文。

### 3.2 对象身份与 magic

- D1 只接受 D0 已冻结的 ORIGINAL key：
  `{environment}/{store_id}/staged/{evidence_id}/original`。
- environment、store/evidence UUID 与 key 必须逐段一致；拒绝路径穿越、反斜杠、控制字符、编码混淆
  或额外段。
- JPEG 要求 `FF D8 FF`；PNG 要求完整八字节签名；WebP 要求 `RIFF....WEBP`；MP4 要求合法长度的
  ISO BMFF box 且首个 box type 为 `ftyp`。
- 实际总字节数必须精确等于声明值，流式累计超过 50 MiB 或声明上限立即中止；实际 SHA-256 必须
  与声明小写 hex 完全一致。

### 3.3 配置

新增 server-only 配置以 `EVIDENCE_STORAGE_*` 命名，至少包括 provider mode、endpoint、region、
bucket、path style、request timeout、upload/read TTL，以及 upload/read/delete 三组 access key、secret
和可选 session token。启用时：

- evidence bucket 必须与 `S3_BUCKET` 不同。
- 三组 evidence access key 必须彼此不同，也不能等于 `S3_ACCESS_KEY`。
- 缺少任一字段、TTL/timeout 越界或凭据复用均启动失败，错误只列字段名。
- production 还必须使用 HTTPS、非仓库 placeholder，并显式配置 `aws:kms` 与 KMS key ID；D1 不把
  “配置存在”当作 provider 侧 KMS/lifecycle 已验证。

默认 mode 为 `disabled`，不得因 `.env` 中存在部分 evidence 字段自动启用。

## 5. 迁移、兼容与回滚

- 数据库变化为无，不新增迁移；D0 schema/outbox/原语保持兼容。
- adapter 为新增内部接口，既有 catalog/content 调用方继续使用 `MediaStorageProvider`。
- 应用回滚只需保持 evidence provider disabled 并注销未来调用方；D1 本身没有调用方或数据库事实。
- 本地 MinIO 初始化只创建独立 bucket/user/policy，重复执行必须幂等。测试对象使用随机前缀并在
  `finally` 删除；bucket/user 不自动递归删除。
- 若未来已有真实 evidence 对象，不能靠应用回滚或 bucket 删除清理；必须沿用 D0 ledger 和后续兼容
  worker 收敛到安全终态。

## 6. 风险与停止条件

- **凭据越界**：MinIO root 只用于 bootstrap；任何应用/测试证据使用 root 即验收失败。content 用户
  必须无法 HEAD/GET/PUT evidence，evidence 用户也不能访问 content bucket 或执行超出角色的操作。
- **metadata 欺骗**：Content-Type、Content-Length 和 provider checksum 只是初筛；未完成实际流式
  digest/magic 校验不得返回成功。
- **内存/慢流攻击**：不得一次性缓冲 50 MiB；必须有总字节上限、请求超时、异常 chunk 拒绝和流中止。
- **URL/key 泄漏**：provider 错误、日志、测试快照和完成报告不得包含签名 query、凭据、对象 key 或
  供应商正文。测试仅断言稳定错误 code。
- **S3 语义差异**：MinIO 通过不等于 AWS/生产通过。checksum、If-None-Match、SSE-KMS 和 lifecycle
  必须在目标 provider/staging 重新验收。
- **版本化删除语义**：当前 delete-only adapter 不接收 version ID。evidence bucket 一旦曾启用版本化，
  普通 DELETE 可能只创建 delete marker，不能证明正文已物理删除；本地初始化因此要求固定 evidence
  bucket 的版本控制从未启用。生产 KMS/lifecycle/versioning/Object Lock 与历史版本物理清理方案未冻结
  前，生产 rollout 必须阻塞。
- **AWS 最小 read IAM 差异**：最小读取身份对不存在对象在 AWS 上可能因缺少 list 权限返回 `403`，
  而非可区分的 `404`。调用方仍须失败关闭；是否通过受控 `HeadObject` 权限或稳定错误映射收口，必须
  在目标 provider/staging 验证，不能用 MinIO 结果代替。
- **错误完成声明**：没有 scanner/worker/HTTP/生产 KMS/lifecycle 证据时，D1 最多标记 repository +
  local/test storage validation `COMPLETE`，不能标记 B2b 完成。

任何最小 IAM 反向测试、真实 bytes 校验、错误脱敏或测试对象清理无法稳定通过时停止 D1 交付。

## 7. 测试与验收

### 7.1 单元与配置

- mode 默认 disabled；部分配置、凭据/bucket 复用、非法 TTL/timeout、production HTTP/placeholder/
  缺 KMS 均失败关闭且不泄密。
- 规范 key 与路径穿越；四种 magic 正反例；长度、checksum、Content-Type、超限和异常流。
- create-only PUT、checksum/header、短期 no-store GET、delete-only client 与供应商错误分类。
- 签名 URL、对象 key 和 provider 原始错误不进入异常消息或快照。

### 7.2 MinIO 集成

- content 身份只能访问 content bucket，无法访问 evidence bucket。
- upload 身份只能 create-only PUT；read 身份只能 HEAD/GET；delete 身份只能 DELETE，三者不能互相
  替代，也不能访问 content bucket。
- 真实上传 JPEG/PNG/WebP/MP4 最小对象并由 read 身份流式复算长度/checksum/magic。
- MIME 欺骗、声明 checksum/长度不匹配、重复覆盖被拒绝；删除后再次读取为 NOT_FOUND。
- 每个测试在 `finally` 通过 delete 身份清理随机对象，并在结束时证明测试前缀无残留。

### 7.3 仓库门禁

- 定向 config/integrations 单元与 D1 infrastructure integration。
- 完整 `corepack pnpm test:integration`、`corepack pnpm verify`、生产依赖 high 审计。
- OpenAPI 结构/引用回归，确认 D1 没有 runtime status 变化。
- Gitleaks、tracked/untracked `git diff --check` 与独立高风险差异复审。
- D1 无 UI/HTTP，专项浏览器 E2E 为 `NOT_APPLICABLE`；不得冒充 Zalo 宿主或生产 storage 证据。
