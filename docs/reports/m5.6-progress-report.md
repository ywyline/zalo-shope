# M5.6 GHN 首家物流供应商进度报告

> 状态：仓库自动化范围已收口；真实 GHN sandbox 与 Zalo 宿主验收 `BLOCKED/NOT_RUN`
>
> 日期：2026-07-26
>
> 范围：`docs/plans/m5.6-implementation-plan.md`

## 1. 结论

M5.6 已完成仓库内 GHN 物流能力实现，但没有真实供应商验收证据。代码只在按商城解析到明确
渠道与 secret reference 后调用 GHN；示例配置保持 `SHIPPING_PROVIDER=disabled`，本次未调用
真实 GHN、未创建测试运单、未生成供应商成功事实，也未提交或推送。

因此本报告只记录“仓库自动化实现完成”。两个商城的真实 ShopId/Token、sandbox 仓库与服务、
测试订单、面单、webhook、COD 能力和 Zalo 宿主验收仍阻塞，M5.6 与整个 M5 均不得标记完成。

## 2. 已实施范围

- `packages/integrations` 提供 GHN 服务列表、报价、建单、取消、主动查单、面单和未签名 hint
  契约；固定 HTTPS origin/path，拒绝 redirect，限制超时、响应字节、JSON 类型与整数范围。
- 报价严格解析基础、保险、COD、偏远与其他已知附加费，持久化 GHN service id/type id，并校验
  五项费用与总额恒等；显式 null、折扣或不一致响应失败关闭，不再把总额冒充基础费。
- 数据库新增商城隔离的仓库履约资料和订单行重量/长宽高快照。联系人、电话与详细地址加密；
  新订单缺少完整 SKU 物理属性时阻断，既有订单不从当前 SKU 虚构回填。
- API 只从可信订单、地址、仓库、渠道、服务和 COD 事实报价/建单，不接受客户端金额、地址、
  重量、供应商单号或状态。管理命令要求 RBAC、近期 MFA、确认词、原因、版本和幂等键。
- worker 通过版本化 outbox 处理建单、取消和查询，网络调用不跨数据库事务。GHN 建单成功只把
  运单推进 `PENDING_PICKUP`；只有主动查询可以按内部状态机推进订单发货/签收。成功 operation
  在 outbox 重放前短路，迟到错误不能把成功覆盖为失败。
- GHN webhook 固定为 `UNVERIFIED_HINT`，只去重并调度主动查询。未知、倒退、拒收、退回和异常
  不自动退款、恢复库存或完成订单。
- 面单通过 60 秒内部 JWT 代理读取，严格校验 GHN origin/path/token query、PDF 类型和 8 MiB
  上限，不向浏览器返回 GHN Token URL。签发与实际读取分别审计。
- 管理端提供仓库履约资料、报价、建单、同步、取消、面单与轨迹工作流；Mini App 提供越南语、
  中文、英文轨迹，以及加载、空、失败和重试状态。双商城继续复用同一套代码与主题配置。

## 3. 数据与迁移

- 前向迁移：`20260726130000_m56_shipping_fulfillment_facts`。
- 新表：`warehouse_fulfillment_profiles`，使用 `(store_id,warehouse_id)` 主键、商城复合外键、
  强制 RLS 和运行角色最小权限。
- 兼容扩展：`order_items` 四项物理快照列保持可空，只为兼容历史订单；新订单由应用强制完整。
- 回滚：只允许无 M5.6 事实的 local/test scratch。有仓库资料、订单物理快照、GHN secret
  reference、运单、operation 或轨迹时以 SQLSTATE `55000` 拒绝，生产只允许向前修复。
