## 1. 阶段结论

B3 已完成三条默认关闭的售后写命令：会员创建、会员取消和管理员创建商家主动退款待审核 case。实现以
商城、真实 actor、持久 session、订单、政策、交付、收款、整数 VND 容量和证据资格为服务端事实源，
在 `Serializable` 事务内原子提交售后 header/items、operation、transition、审计及必要的 evidence
claim。商家主动退款只形成 `MERCHANT_REFUND + PENDING_REVIEW`，不执行退款 provider、库存动作、到账
确认、返件或换货履约。

该结论只允许将 **B3 default-disabled repository implementation + local/test validation** 标记为
`COMPLETE`。`AFTER_SALE_COMMANDS_ENABLED` 默认 `false`；production 配置解析与服务层都拒绝启用。
生产政策、TTL、对象存储、真实支付/物流供应商、部署、rollout 和 Zalo 真机均为
`NOT_AUTHORIZED / NOT_RUN`。B4-B7、UI、完整 B2/B2b、M6.3、M6 与 P0 继续未完成。

## 2. 已实现范围

### 2.1 API、契约与稳定命令结果

- 注册 `POST /v1/after-sales`、`POST /v1/after-sales/{afterSaleId}/cancel` 与
  `POST /v1/admin/orders/{orderId}/after-sales`，分别复用会员/管理员 WRITE 限流、严格 DTO、服务端
  correlation ID、`private, no-store` 与稳定错误投影。
- 三条写命令只返回不可变 acknowledgement：`id`、`public_number`、命令完成时的 `status` 与
  `version`。幂等重放从 operation `result_summary` 重建原结果；case 后续取消或其他状态变化不会改写
  原创建响应。当前完整聚合、金额、政策、凭证状态与时间线必须通过 GET 查询。
- request hash 绑定商城、actor、operation、规范 path/body/target 与 idempotency-key hash；同键异参或
  跨主体复用稳定冲突。公开号使用独立的 128-bit 随机值 `ASC-` + 32 位大写十六进制，不从内部 UUID
  推导。

### 2.2 商城、主体、RBAC 与最终授权

- 会员命令只信任 Bearer/Header 解析的当前商城、当前会员和未撤销未到期 session；已知跨商城、跨会员
  或跨订单资源保持不可枚举。
- 管理员商家主动退款要求目标商城直接授予的 `store.after-sales.review` 和近期 MFA。当前身份模型不能
  在 B3 事务中证明平台来源 scope 与目标商城权限的 conjunction，因此仅有
  `platform.stores.cross_access` 固定返回 `403`；`X-Access-Reason` 不能替代目标商城直接权限。
- 首次执行和幂等重放都在持锁事务内复验 ACTIVE 商城、actor、Bearer/session 截止、会员归属，以及
  管理员当前 RBAC/MFA。锁等待期间会员授权失效映射 `401`，管理员授权失效映射 `403`。

### 2.3 政策、交付、收款、金额与证据

- 非 legacy case 的订单行必须解析为同一不可变 policy/version/hash；原因命中
  `allowed_reason_codes`，申请窗口按 `Asia/Ho_Chi_Minh` 自然日和权威 `ORDER_OUTBOUND` 交付事实计算。
  旧订单缺少一致政策时会员 case 仅进入 `REVIEW_REQUIRED`，不能取消；管理员 merchant refund 不接受
  legacy。
- 第 49 段在任何 DDL 前只读检查 policy 草稿、已发布版本、订单行快照和非空售后快照：三个 reason 数组
  必须类型/数量/code/唯一性合法，evidence/opened-package reason 必须是 `allowed_reason_codes` 子集。
  不兼容事实以 `55000` 停止且不改迁移目录状态，不输出、猜测或回填历史 payload。
- 当前只接受 VND、已交付/完成且具有唯一可信 ONLINE 成功收款事实的订单。仓库没有可供 B3 锁定并
  复验的 COD 已确认收款事实，因此所有 COD B3 创建均失败关闭；这不是 COD 售后已交付的声明。
- 服务端按历史售后占用重算剩余数量、逐行 VND 余数和每订单一次 merchant-paid 运费权益；不接受客户
  端金额。exchange 只允许 ACTIVE、同 SPU、不同 SKU、等价价格且仅政策指定属性变化。
- 只有政策/原因要求凭证或请求携带非空 `evidence_ids` 时，上传校验、恶意扫描、claim、protected
  read、删除补偿及显式 `ordinary < retention` TTL 才全部成为强制条件。无凭证且政策不要求时命令不
  依赖这些可选 capability；触发条件成立时任一能力缺失均在写入前失败关闭。
- evidence claim 与 case header/items/operation/transition/audit 同事务提交。取消不 unclaim、不缩短
  ordinary/retention deadline、不删除对象，也不执行退款或库存动作。

### 2.4 事务、幂等重试与数据库完整性

- create/cancel 只对 Prisma `P2034` 或 PostgreSQL `40001` 做最多三次 Serializable 事务尝试（首次加
  最多两次重试）；`expected_version` 冲突明确排除在重试之外并稳定映射为版本冲突。随机公开号碰撞有
  独立三次上限。
- 完整并发回归同时暴露既有 B2a 政策命令在 Serializable 快照建立后等待商城 advisory lock 的竞态：
  同键新建草稿的败者可能先撞 policy 唯一键而非读到幂等赢家。唯一冲突回滚后现只在新的
  `ReadCommitted` 商城事务中读取同 operation/key 的未过期已提交记录，严格核对 request hash 和响应
  schema 后回放；没有赢家时保留原唯一约束错误分类，不重跑无关业务命令。确定性集成测试会先阻塞并
  观察两个 API backend 同时等待该锁，再验证一次创建、一次回放及单份 policy/audit/idempotency 事实。
- 第 49 段迁移 `20260731110000_m63_b3_after_sale_commands` 为 transition 增加 operation 复合绑定、
  每 case 唯一 `SUBMIT`、operation 完成/链接 guard、deferred runtime case commit guard 和两项窄
  security-definer finalizer。审批 item/header/allocation/legacy-approve 的 early guard 与 B3 create 共用
  per-order advisory lock；行锁后遇到竞争时以 `40001` 回滚整笔审批，transition lock trigger 则明确排在
  B0 contract guard 前，避免反向等待形成 deadlock。
- 普通 runtime 的 `after_sale_operations INSERT` 已撤销，只能执行窄 submit/cancel 函数；member 不能
  裸写 header、operation 或 transition。创建使用 `SUBMIT`，取消使用 `CANCEL`，并要求 allowlist 审计与
  operation 在提交时成套存在。
- `down.sql` 仅限无 B3 业务事实的 local/test；存在 B3 `SUBMIT`、operation、审计或预留 outbox 时以
  SQLSTATE `55000` fail-fast。生产或已有命令事实的数据库只允许经审查的前向修复。

## 5. 已知限制与生产阻断项

1. **生产策略与 TTL 未批准**：`.env.test.example` 的 30/90 天只用于 local/test 自动化，不是隐私、DPO、
   合规或生产保留结论。
2. **生产对象存储与 evidence 控制面未验收**：local/test MinIO/ClamAV 不能证明目标 IAM/KMS/HTTPS/
   versioning/Object Lock/lifecycle、legal-hold/dead-letter 管理、外部告警或 bearer-URL 风险接受。
3. **真实供应商与 COD 收款事实缺失**：B3 不调用真实支付/退款/物流 provider；当前 COD 没有可证明的
   确认收款事实并全部失败关闭。B6/B7 仍须单独规划和授权。
4. **管理员跨商城写保持关闭**：当前身份模型不能证明 B3 所需的目标商城直接 review 权限 conjunction；
   cross-access-only 不是替代路径。若未来开放，必须先更新身份契约、审计、迁移/测试和本计划。
5. **后续售后状态机未交付**：审核/拒绝、legacy 决定、返件、验收、退款协调、库存恢复与换货履约属于
   B4-B7/M6.4；B3 merchant refund 不是已批准或已成功退款。
6. **无专用 OpenAPI 3.1 语义 linter**：当前只证明严格 YAML 与本地引用完整。
