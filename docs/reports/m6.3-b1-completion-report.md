## 2. 已完成事实

### 2.1 商城、主体与权限边界

- 会员查询显式绑定 `store_id + member_id`；详情中的跨会员、跨商城和不存在统一为当前 scope 内的
  `404`。管理员先经过中央 `store.after-sales.read` 授权，再显式绑定 query/header 商城与 `store_id`。
- 应用条件之外继续叠加 PostgreSQL FORCE RLS。集成测试使用真实 runtime role 覆盖已知跨商城 UUID、
  跨商城 member/order filter、Header/query 不一致和无权限管理员。
- 四个 GET 统一返回 `Cache-Control: private, no-store`，成功及错误使用同一个安全 correlation ID。

### 2.2 稳定分页与严格输入

- 会员固定 `created_at DESC, id DESC`，管理员固定 `updated_at DESC, id DESC`；数据库读取
  `limit + 1` 后仅按白名单 ID 批量投影。
- 游标保存 PostgreSQL 六位微秒 UTC 文本，并使用原生 tuple seek，避免 JavaScript `Date` 的毫秒截断。
  HMAC-SHA-256 游标绑定商城、主体、资源、规范筛选、排序键、UUID 与过期时间。
- `AFTER_SALE_CURSOR_HMAC_KEYS` 支持 1-3 把唯一 base64url key；第一把签发、全部验证。production
  会逐把拒绝公开的 local/test 占位键，即使占位键与真实键混排也失败关闭。
- 列表、详情、path、header 与 query 均使用严格 schema；会员详情不再忽略未知 query，商城代码与
  OpenAPI 的长度和字符模式一致。

### 2.3 公共投影、本地化与资金引用

- Prisma `select` 只读取响应必需列，不把 evidence object key/扫描事实、内部审核原因、timeline actor/
  reason/correlation、transfer digest/密文或 provider payload 读入进程。
- Evidence 只公开 `PENDING/READY/UNAVAILABLE`；返件只公开承运商、脱敏单号、状态与提交时间；settlement
  只公开公开号、方式、状态、整数 VND、公开退款号和时间。
- 会员 locale 为 `preferredLocale -> vi`，管理员为显式 locale、商城默认、`vi`。非 legacy 必须同时
  具备绑定政策、不可变版本、越南语本地化和非空原因详情；缺任一事实均失败关闭，不能借当前活动政策
  或 nullable 字段伪造历史事实。legacy 政策字段保持全 null。
- 金额只接受 `0..Number.MAX_SAFE_INTEGER` 的整数 VND；响应最终再次通过严格 Zod schema 验证。

### 2.4 限流、数据库与契约

- Redis 固定 60 秒窗口：会员 60 次、管理员 120 次，key 绑定商城和 HMAC 后的主体。超限在目标查询前
  返回安全 `429 + Retry-After`；Redis 不可用时在查询前失败关闭为 `503 UPSTREAM_UNAVAILABLE`，
  不承诺 `Retry-After`。
- 新迁移 `20260728110000_m63_b1_after_sale_admin_read_index` 增加
  `(store_id, updated_at DESC, id DESC)`；Prisma 同步数据库既有
  `after_sale_refunds(store_id, settlement_id)` 唯一约束，不重复创建迁移。
- OpenAPI 仅把四个 B1 GET 标记为 `implemented_m6_3_b1`，同步 400/503、correlation、no-store、
  `X-Access-Reason` 和 legacy/evidence `oneOf`；B2-B7 保持 `contract_only_m6_3_b2_to_b7`。

## 3. 独立审查修复

独立高风险复审没有发现最终候选存在直接跨商城泄漏或敏感密文外泄，但在收口过程中发现并修复：

1. production key ring 占位检测原先只比较整串，现改为逐键拒绝并覆盖占位键前置/后置混排。
2. 目标语言存在时原先未强制越南语基线，现先证明 `vi` 再执行目标语言回退。
3. 非 legacy 的 `reason_detail_ciphertext=null` 原先可能投影 null，现 projector 与响应 schema 双层失败关闭。
4. 会员详情未知 query、商城代码 pattern、Redis 503 和管理员跨商城 access reason 的运行时/OpenAPI 漂移已关闭。
5. 管理员微秒分页、管理员游标重放、跨商城 filter、真实 Refund 公开号关系、证据期限和 429 分钟边界
   测试已补强。

## 5. 风险与未完成边界

- 管理员游标按可变 `updated_at` 跨 HTTP 请求分页；期间记录被更新可能移动到已遍历区间。需要一致刷新时，
  客户端必须从第一页重启，B1 不提供跨请求数据库快照。
- 新索引使用普通 `CREATE INDEX`。本轮未部署；生产大表 rollout 前必须评估表规模、锁等待和维护窗口，
  必要时另行批准并设计并发索引迁移，不能直接在事务迁移中偷换语义。
- Redis 故障会使四个读取接口返回 503，这是防止静默绕过限流的有意可用性取舍；上线前需要 Redis
  健康检查、告警和容量验证。
- 密钥轮换必须“新键置首、保留旧键、等待最长 TTL、再移除退役键”；提前移除会让有效分页游标返回 400。
- 生产审计仍有 3 项 `react-router/react-router-dom@6.30.4` moderate 公告。当前门禁只要求 high 以上；
  ZMP UI 兼容升级和导航安全回归仍需在生产发布前完成，不能描述为零漏洞。
- B2-B7、完整返件验收与 exactly-once 库存恢复（M6.4）、售后 UI、生产政策/enforcement、真实供应商、
  Zalo 宿主真机、部署、提交、推送和发布均未授权或未验证。

本轮没有创建生产政策、写入真实凭据、调用供应商或修改生产数据。工作区保持未提交状态。
