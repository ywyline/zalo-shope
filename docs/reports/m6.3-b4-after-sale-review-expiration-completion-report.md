## 1. 阶段结论

B4 已完成两条默认关闭的管理员售后写命令和一个独立 SYSTEM 寄回到期 worker。非 legacy 初审可批准
或拒绝 `PENDING_REVIEW`；manual/legacy 路径可一次性决定历史 case，或按数据库冻结的
`review_resume_status` 恢复/早期拒绝普通人工复核。所有批准金额由服务端根据请求行与冻结整数 VND
权益重算，客户端不能提交金额。商家主动退款必须由不同管理员复核。

该结论只允许将 **B4 default-disabled repository implementation + local/test validation** 标记为
`COMPLETE`。`AFTER_SALE_REVIEW_COMMANDS_ENABLED` 与
`AFTER_SALE_RETURN_EXPIRATION_WORKER_ENABLED` 默认 `false`，production 配置明确拒绝启用，service 也
对 production 审核失败关闭。B4 不执行真实退款/COD，不创建返件物流、验收、库存恢复、换货履约或 UI。
生产政策、外部供应商、部署和 rollout 均为 `NOT_AUTHORIZED / NOT_RUN`；B2/B2b、B5-B7、M6.3、M6
与 P0 继续未完成。

## 2. 已实现范围

### 2.1 管理员 API、安全边界与幂等结果

- 注册 `POST /v1/admin/after-sales/{afterSaleId}/review` 与
  `POST /v1/admin/after-sales/{afterSaleId}/resolve-review`，严格绑定 Store-Code、目标 case、管理员
  Bearer/session、Idempotency-Key、来源 IP 和服务端 correlation ID。
- 两条命令要求目标商城直接 `store.after-sales.review`、近期 MFA、确认词、至少 10 字符 reason、expected
  version 与 ADMIN WRITE 商城+主体限流。只有 `platform.stores.cross_access` 不能替代目标商城权限。
- 首次执行和幂等重放都在持锁事务内重验 ACTIVE 商城、管理员/会话/token、近期 MFA 和直接 RBAC。
  request hash 绑定商城、actor、path、operation、规范 body 与幂等 key hash；同键异参稳定冲突。
- 成功只返回 operation 中冻结的 `id/public_number/status/version` acknowledgement；后续聚合状态通过 B1
  GET 读取。reason 不写入公开响应，legacy `policy_basis` 先规范化、加密并保存摘要。

### 2.2 服务端 VND、maker-checker 与人工复核

- `ADMIN_REVIEW` 仅接受非 legacy `PENDING_REVIEW`。批准必须唯一且完整覆盖全部请求行，至少一行正数，
  任一数量不得超过申请量；拒绝不能夹带批准行。
- 逐行批准金额按 `requested_item_vnd * approved_quantity / requested_quantity` 向下取整；批准全部申请
  数量时取得该行完整余数。正数批准复用已冻结申请运费/其他额并同事务写订单 allocation，客户端金额
  永不进入持久事实。
- `MERCHANT_REFUND` 创建管理员不得审核自己发起的 case；目标商城另一名具备直接权限和近期 MFA 的
  管理员才能批准或拒绝。
- legacy case 只允许一次 `LEGACY_APPROVE/LEGACY_REJECT`。批准按既有请求行全量冻结，不把当前政策
  伪造成历史事实；退货类必须提交一次性期限和运费承担方，非退货类拒绝这些字段。
- 普通人工复核 `RESUME` 只能回到数据库冻结的同类型状态；`REJECT` 只允许冻结状态为
  `APPROVED/RETURN_PENDING`，并在事务内证明没有资金、返件、验收、库存、换货或非订单运单副作用。

### 2.3 寄回截止、SYSTEM worker 与竞态

- 普通退货退款/换货批准按冻结 `policy_snapshot.return_window_days` 和 `Asia/Ho_Chi_Minh` 越南自然日
  计算排他 `return_deadline_at`；批准日不消耗一个完整寄回日。
- worker 只在独立开关开启时枚举 ACTIVE 商城，为每个商城创建固定 SYSTEM actor、
  `after-sale-transition` scope 和独立 correlation ID；单商城失败不会阻断其他商城。
- 数据库批次按 `(store_id,status,return_deadline_at,id)` 索引读取到期
  `APPROVED RETURN_REFUND/EXCHANGE`，以 `FOR UPDATE SKIP LOCKED` 追加唯一
  `RETURN_EXPIRED: APPROVED -> REJECTED` 和 SYSTEM audit。
- 到期与后续返件共享售后聚合锁和既有状态/副作用 guard；并发批次、重复轮询或返件竞争至多一个成功。
  worker shutdown 先停止新批次并等待 active run，再由应用统一断开数据库。

### 2.4 迁移、数据库完整性与回滚

- 第 50 段 `20260731130000_m63_b4_after_sale_review_expiration` 增加到期索引、三项窄
  security-definer runtime 函数、operation completion guard 和 deferred operation/transition/audit
  原子 guard；PUBLIC 及普通 runtime 不能执行内部 guard，只授予精确入口。
- 第 51 段 `20260731131000_m63_b4_atomicity_name_fix` 只向前修复 deferred atomicity 函数中 PL/pgSQL
  局部变量与列名歧义，不改写业务事实。
- 审核/复核使用 `Serializable`，只对 Prisma `P2034` 或 SQLSTATE `40001` 最多尝试三次；明确
  expected-version 冲突不重试。到期批次使用有界 `ReadCommitted` 事务。
- operation、恰一条 transition 与 allowlist audit 必须同事务提交。第 50 段 `down.sql` 仅允许无 B4
  operation/review/expiration audit 的 local/test；存在事实以 SQLSTATE `55000` 停止。生产及已有 B4
  事实环境只允许经审查的前向修复。

## 5. 已知限制与生产阻断项

1. **生产政策未批准**：退货期限、运费承担、legacy 历史依据和人工复核规则仍需业务、隐私与越南合规
   审批；local/test 默认值不是法律意见或生产配置。
2. **没有真实退款或 COD 结算**：B4 批准只写售后金额/状态事实，不创建 M5 refund、provider outbox、
   COD 应付或到账事实。后续资金动作属于 B6/B7 独立计划。
3. **没有返件、验收和库存恢复**：到期 worker 只在无可信返件/副作用时拒绝 case；B4 不接受会员物流
   声明，不创建 return shipment，不执行 inspection 或 exactly-once 库存恢复。
4. **没有换货履约**：批准 exchange 不预留 replacement，不创建 `EXCHANGE_OUTBOUND`，也不处理价差。
5. **管理员跨商城写保持关闭**：cross-access-only 不能替代目标商城直接 review 权限；若未来开放，必须
   先更新身份契约、审计、迁移和安全测试。
6. **无专项 UI/E2E 和 OpenAPI 语义 linter**：B4 只有 API/database/worker；三语移动端、Zalo 真机和
   OpenAPI 3.1 完整语义仍未验收。
