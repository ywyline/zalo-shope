## 2. 已实现范围

- 注册 `POST /v1/after-sales/evidence-uploads`、
  `POST /v1/after-sales/evidence-uploads/{evidenceId}/confirm` 与
  `GET /v1/after-sales/evidence-uploads/{evidenceId}`。
- 三条路由绑定有效 member Bearer、`X-Store-Code`、token `store_id`、owner FORCE RLS、correlation ID
  和商城+会员 Redis READ/WRITE 限流。限流在 evidence 查询/写入前失败关闭。
- 初始化复用 D0 SERIALIZABLE 配额锁、24 小时幂等、规范 ORIGINAL key 和 expire outbox；数据库提交
  后由 D1 upload 身份签发 create-only URL。同键重试只为同一 evidence 重签，不重复占用配额。
- 上传响应新增严格 `upload_headers` allowlist，只允许完成签名 PUT 必需的 Content-Type、create-only、
  SHA-256 checksum 和可选 SSE header；不返回 object key、bucket、凭据或内部截止点。
- 确认前从 owner 声明加载内部规范 key，由 D1 read 身份执行 HEAD + `If-Match` GET，按实际 bytes
  重算长度、SHA-256 和 JPEG/PNG/WebP/MP4 magic。验证通过后 D0 重新取锁复核 owner/version/deadline，
  原子确认并排队 scan；HTTP 校验本身不产生 `CLEAN`。
- D2 worker 仍以固定 evidence SYSTEM scope 从权威 ledger 独立重读、复验和扫描。会员 HTTP 没有
  SYSTEM-only ledger SELECT，也不能提交扫描结果。
- owner 状态只投影 `PENDING/READY/UNAVAILABLE`，使用数据库时钟执行排他 upload/claim/ordinary
  access 截止。恶意、失败、隔离、删除与内部错误统一折叠为 UNAVAILABLE。
- `AFTER_SALE_EVIDENCE_MEMBER_UPLOADS_ENABLED` 默认 `false`。启用必须同时配置 D1 S3、D2 ClamAV、
  upload TTL 和未 claim 数量/字节配额；签名 URL TTL 不得超过数据库 upload TTL。
- D3 不新增 schema、RLS、grant、trigger、enum、STORE 权限或迁移，M2→current 保持 43 段。

## 5. 安全与事务不变量

- 初始化数据库提交与 URL 签发不是同一事务。签发失败稳定返回 `503`，同一幂等键只重签同一规范
  identity；不得在 provider 成功后用第二个数据库事务创建另一 evidence。
- 确认的对象网络读取不持有数据库锁。验证后必须重新取得配额/evidence 锁并复核 expected version、
  owner、状态和数据库截止；TOCTOU 变化只允许冲突，不能使用先前网络结果覆盖新事实。
- member 查询只读取 owner 父行声明；D1 校验规范 key，D2 再从 SYSTEM-only ledger 读取权威 binding。
  客户端 URL、key、header 或 provider metadata 都不能成为授权或扫描身份。
- confirm replay 只返回已提交确认事实，不重新读对象或重复排队 scan。不同请求复用同一幂等键稳定
  冲突；所有公共错误和响应使用 allowlist，不泄露对象/scanner/provider 细节。
- READY deadline 为排他边界；legal hold 不延长普通读取。未确认对象即使 expire worker 尚未投影，
  upload deadline 到达后 owner 状态也立即变为 UNAVAILABLE。

## 6. 已知限制与生产阻断项

1. **没有 expire/delete worker**：初始化会可靠排队到期消息，但 D3 不消费。生产启用会形成无法物理
   清理的对象与事实，因此 capability 必须继续关闭，直至删除协调、provider 幂等/not-found、重试/
   耗尽和告警均有运行证据。
2. **scanner disabled 不是暂停语义**：已有 scan 消息可能由通用 outbox 作为 unsupported handler
   进入死信。任何关闭或回滚必须先停止新初始化/确认，并让兼容 worker 收敛已有消息。
3. **生产存储仍受版本化删除阻断**：当前 adapter 没有 version ID；versioning/Object Lock 下普通
   DELETE 不能证明旧正文物理删除。目标 provider 的最小 read IAM 不存在对象错误语义也未验收。
4. **local/test ClamAV 不是生产证明**：网络隔离、签名更新/freshness、HA、50 MiB 最坏时延、吞吐、
   容量、监控、告警和 SLA 仍待目标环境审批与验证。
5. **示例 TTL/配额不是法律结论**：production upload/claim/access/retention、数量和字节配额必须由
   越南业务、隐私/DPO 和合规人员批准，不能直接沿用 `.env.test.example`。
6. **无专用 OpenAPI 3.1 语义 linter**：当前只证明严格 YAML 与本地引用完整；语义 linter 缺口保留。

## 7. 回滚与后续

- 首先将 `AFTER_SALE_EVIDENCE_MEMBER_UPLOADS_ENABLED=false`，停止新初始化/确认；已有 scan 消息继续由
