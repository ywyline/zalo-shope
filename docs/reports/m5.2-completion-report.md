# M5.2 支付、物流与可靠消息数据基础完成报告

> 状态：已按批准的受限无凭据路径完成仓库内实现与本地自动化收口；真实供应商集成未验收
>
> 日期：2026-07-25
>
> 范围：`docs/plans/m5-implementation-plan.md` 的 M5.2；不包含运行时 API、worker、外部调用、
> 买家/管理 UI、真实渠道启用或供应商 sandbox 验收

## 1. 已交付

- Prisma 新增商城支付/物流渠道、支付尝试/转换、供应商回调、退款/转换、物流报价、运单/行、
  轨迹、物流 operation、outbox 和 inbox 共 14 个模型；订单支付投影向后兼容增加部分退款和
  全额退款。
- 所有 M5 商城表包含 `store_id`、复合商城关系并强制 RLS；没有事务级商城上下文时默认拒绝。
  支付、订单、渠道、退款、仓库、运单和订单行不能跨商城拼接。
- 支付尝试金额/币种通过复合外键绑定订单应付快照；活动支付尝试和活动运单使用部分唯一索引。
  VND 金额、费用分解、版本、状态时间和 hash 格式由数据库约束保护。
- 退款创建锁定成功支付行，并把请求中、处理中和成功退款合计限制在已捕获金额内，避免并发
  超额退款。
- Zalo Checkout 回调必须匹配支付渠道；GHN webhook 只能保存为
  `NOT_AVAILABLE/UNVERIFIED_HINT`，不能伪装为已验签权威事实。多态 inbox 同样校验商城、渠道、
  供应商和环境。
- 支付/退款转换、物流报价、运单行和轨迹为不可更新/删除事实；其他 M5 聚合禁止删除。运行
  角色对可变表只获得受审配置、状态、供应商结果和重试列的更新权限，不能修改金额、归属、
  幂等或请求身份。
- 权限目录登记 12 项 `store.payments.*`、`store.refunds.*`、`store.shipments.*`、
  `store.integrations.*` 和任务重试权限，不自动赋予生产角色。local/test seed 不创建支付/物流
  渠道或任何业务事实。

## 2. 迁移与向前修复

| 迁移                                                      | 作用                                                       |
| --------------------------------------------------------- | ---------------------------------------------------------- |
| `20260725090000_m52_payment_shipping_foundation`          | 14 张表、枚举、复合外键、索引、约束、RLS、只追加和回滚门禁 |
| `20260725093000_m52_permission_catalog`                   | 登记 12 项 M5 权限，不给生产角色自动扩权                   |
| `20260725100000_m52_callback_trust_guard`                 | 固定 GHN 回调只能是未验证同步提示                          |
| `20260725103000_m52_payment_amount_and_permissions_guard` | 绑定订单金额/币种并把运行角色整表更新收缩为列级最小授权    |

前三条迁移在本地部署并获得测试证据后未被改写。最终审查发现支付金额尚未由数据库绑定订单、六张
可变表仍有整表更新权限，因此使用第四条向前迁移修复，避免迁移 checksum 漂移。

每条 `down.sql` 只允许无渠道、无 M5 业务事实的 local/test scratch。存在渠道、支付、退款、回调、
运单、轨迹或消息事实时以 SQLSTATE `55000` 拒绝；生产和已有事实环境只允许向前修复。

ZMP SDK 2.51.8 已是最新稳定版，且其发布代码不引用误列为生产依赖的 `@babel/cli`；新增精确 pnpm
override 移除该 CLI 后，冻结安装、Mini App 307 模块生产构建、完整 `verify` 和生产审计通过。

第一次最终集成复跑时 Docker 中的 PostgreSQL、Redis、MinIO 同时异常退出，导致连接前失败；按
项目 `infra:up` 恢复后确认 20 份迁移和 seed 完整。第二轮出现一次既有 M3.5 `ECONNRESET`，容器
未重启且持续健康，M3.5 定向 11/11 及随后完整 121/121 均通过。这两轮不计为成功证据。

全目录 Gitleaks 会按预期发现 Git 忽略的本机 `.env` 和生成目录测试哨兵；这些不是提交候选，
未读取、修改或报告其值。最终扫描只覆盖 Git 历史、已跟踪差异和未忽略的未跟踪候选文件。

M5.2 没有运行时 API 或 UI 变化，因此浏览器 E2E 不适用；不以 M4 E2E 冒充 M5 支付/物流验收。
真实 Zalo Checkout/ZaloPay、GHN、HTTPS 回调和 Zalo 宿主真机均为 `NOT_RUN/BLOCKED`。

## 4. 风险边界确认

| 风险项      | M5.2 证据                                                                 | 保留边界                                                   |
| ----------- | ------------------------------------------------------------------------- | ---------------------------------------------------------- |
| 多商城/RBAC | 14 表强制 RLS、复合外键、12 权限只登记、运行角色列级授权                  | 渠道管理 API、MFA/二次确认和生产角色赋权在后续阶段实现     |
| 支付金额    | 整数 VND、订单金额/币种复合绑定、供应商引用唯一、客户端结果不形成成功事实 | 回调验签、主动查单和只消费一次库存属于 M5.4/M5.5           |
| 退款        | 成功支付行锁和在途/成功金额容量上限                                       | 退款命令、供应商调用、对账和工作台属于 M5.7                |
| 物流        | 运单/订单/仓库/行复合归属、活动运单唯一、轨迹只追加、GHN 回调不可信       | 真实报价、建单、面单、查轨迹和 COD 对账属于 M5.6/M5.7      |
| 可靠消息    | outbox/inbox 唯一键、状态/租约字段、身份列不可改                          | `SKIP LOCKED` worker、退避、死信和人工重放属于 M5.3        |
| 凭据与事实  | seed 不创建渠道/业务事实；仓库候选文件无泄漏                              | 两商城 secret reference、sandbox 账户和 HTTPS 回调尚未提供 |
