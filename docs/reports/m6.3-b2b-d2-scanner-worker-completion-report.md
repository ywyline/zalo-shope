## 2. 已实现范围

- `packages/config` 增加默认 `disabled` 的 `EVIDENCE_SCANNER_*`、claim/failed retention 与 scan
  dead-letter 配置。ClamAV 必须与 D1 S3 storage 同时启用；production 只接受显式 loopback sidecar。
- 没有 heartbeat 的租约预算为 `HEAD + max(GET, scanner) + 2 * 2000ms + 5000ms`。默认 10 秒
  storage/scanner 超时组合下，`OUTBOX_WORKER_LEASE_MS=28999` 失败，`29000` 与默认 `30000` 通过。
- `AfterSaleEvidenceScanner` 在单一 `zIDSESSION\0` TCP 连接执行 VERSION/INSTREAM/END。响应 request
  ID、顺序、NUL、UTF-8、上限、产品名、engine version、签名版本/时间与 freshness 全部严格校验；
  总正文最大 50 MiB，单个 INSTREAM frame 最大 64 KiB。
- 只有精确 `stream: OK` 投影 `CLEAN`；严格 `FOUND` 投影 `MALWARE_DETECTED`。malware signature、
  socket/provider 正文、对象 key、checksum 和签名 URL 不记录、不返回、不持久化。
- D1 storage consumer 先 HEAD 并取得非空 ETag，再以 `If-Match` GET 冻结对象。实际长度、SHA-256、
  magic 与 scanner 消费同一有界流；提前返回、流异常、对象替换或任一校验失败都 abort 并拒绝结果。
- `loadAfterSaleEvidenceScanWorkForLease` 与 `applyAfterSaleEvidenceScanResultForLease` 使用固定 evidence
  SYSTEM scope，严格复核商城、scan v1 payload、outbox version/status/owner/lease 和 evidence
  version/generation/status。两个 SERIALIZABLE 事务各限制为 2 秒，并在 evidence 行锁等待后重新读取
  `clock_timestamp()`；截止点相等、等待跨截止点、旧 owner/version 均拒绝。
- legal hold 等同状态更新只推进 evidence version 时，旧 scan identity 会在同一 SYSTEM 事务推进
  generation/version 并排队新的权威 scan outbox；已有当前身份时保持幂等，旧 worker/dead letter
  只能 `SUPERSEDED`。
- 持久、有界 scan dead-letter 轮询重新锁定消息与 evidence。当前权威待扫描对象收敛为稳定
  `SCAN_OUTBOX_DEAD_LETTER/FAILED` 并排队 expire；旧 version/generation 不污染新事实。
- outbox、scan dead-letter 与库存轮询在 `onModuleDestroy` 停止继续领取并等待在途工作；共享 Prisma
  与 S3 client 只在随后的 `onApplicationShutdown` 释放。Nest 实际生命周期测试验证扫描完成前不会
  销毁 storage。
- local/test Compose 固定官方 ClamAV 1.5.3 digest、UTC 时区、健康检查和 50 MiB 以上 stream 上限。
  D2 无 schema/RLS/grant/trigger/enum/迁移变化，迁移总数保持 43。

## 5. 租约、版本与失败收敛不变量

- loader 返回 work 不是提交授权；result primitive 必须重新锁消息/evidence 并使用数据库当前时钟复核租约。
- outbox 先锁、evidence 后锁；即使 evidence 锁等待跨过 lease 截止点，后续也不能使用事务开始时的陈旧时间。
- 结果投影与 expire outbox 原子提交。投影后、generic complete 前崩溃时，重领只完成已 superseded 的旧
  scan message，不重复投影或排队 expire。
- 同状态版本漂移若没有当前 scan identity，必须原子生成下一 generation；若已有当前可收敛 identity，
  不得重复创建。`COMPLETED` 历史消息不能冒充可收敛的当前身份。
- transient scanner/storage 错误在尚有 attempt 时交给通用 outbox 有界重试；最终 attempt 或持久死信
  必须收敛为 `FAILED`，确定恶意进入 `QUARANTINED`，只有确定 CLEAN 进入 `READY_UNCLAIMED`。

## 6. 已知限制与生产阻断项

1. **scanner disabled 不是暂停消费语义**：通用 outbox 不按事件类型预过滤。已有 scan 消息在未注册
   handler 时可能按 unsupported handler 进入死信；当前凭证 HTTP producer 尚未开放，因此不阻断 D2，
   但生产切换前必须先排空/阻止新消息或设计事件过滤，不能直接关闭 scanner。
2. **dead-letter 容量未验证**：候选按 `completed_at, id` 排序，当前没有该窄查询的专用索引。local/test
   有界正确性已验证，大规模积压容量与查询计划尚未验收。
3. **local/test ClamAV 不是生产证明**：尚未验证生产网络隔离、签名库更新、freshness 监控、HA、吞吐、
   50 MiB 最坏时延、容量、告警或 SLA。Clamd TCP 本身没有认证/TLS，只能按受审 sidecar 边界部署。
4. **没有 heartbeat**：配置预算只能阻止已知超时组合明显超过租约；目标环境若无法在预算内稳定扫描
   50 MiB，必须停止 rollout 并另行设计续租，不能放宽提交时 lease 校验。
5. **本地 TTL 不是生产政策**：`.env.test.example` 的 24 小时 claim/failed retention 仅为测试基线，
   不代表越南合规、客服或存储成本审批。
6. **后续能力仍缺失**：HTTP、B3 claim、保护读取/审计、expire/delete worker、物理删除补偿、外部
   告警和 production storage/scanner/rollout 均未完成；B2b/B2、B3-B7、M6.3、M6 与 P0 继续未完成。

## 7. 回滚与后续

- 应用回滚必须先停止新的 scan consumer。已有 evidence/outbox/transition 事实不能删除；兼容 worker/
  reconciler 必须继续把消息收敛到安全终态。
- local/test 可以停止 ClamAV 容器，但不得删除 MinIO bucket、签名库卷或数据库事实作为应用回滚。
- production 或已有真实凭证事实的环境只允许受审前向修复；D2 没有新增可执行的数据库 down 迁移。
- 后续 HTTP、B3-B7、生产配置和 rollout 均须重新计划并取得用户授权。
