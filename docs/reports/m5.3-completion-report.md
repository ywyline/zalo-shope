## 1. 已交付

- 新增商城事务内 outbox 追加原语。`event_type` 与 `event_version` 分列，同商城幂等键并发冲突
  返回首次一致事实；相同键但聚合、事件、重试上限或 payload 不同则稳定拒绝。
- outbox payload 必须是带匹配 `store_id` 的普通 JSON object，最大 16 KiB，并拒绝
  secret/token/authorization/private-key/raw-body 等敏感键。M5.3 前向迁移把 payload 商城身份、
  租约与终态字段组合提升为数据库约束。
- worker 沿用 `app_security.list_active_stores()` 可信商城注册表，不使用 RLS bypass；每个商城建立
  transaction-local `StoreContext` 后，以 `FOR UPDATE SKIP LOCKED` 领取短租约。领取递增尝试次数，
  完成/失败必须匹配商城、owner、未过期租约和 expected version。运行时每轮最多处理配置的
  batch 数量，但每条只在即将执行前领取，避免串行等待消耗后排消息租约。
- 过期租约可由其他实例恢复；最后一次尝试期间进程失效时，下一轮扫描转入 `DEAD_LETTER`。
  可重试失败使用有限指数退避和 20% 抖动，默认 1 秒起步、5 分钟封顶；永久失败和人工复核
  直接死信。所有失败只保存稳定类别，不删除消息或记录上游原文。
- Inbox 使用 `(source, channel_id, environment, external_message_key)` 数据库唯一键完成并发去重；
  同键同摘要返回首次记录，同键不同摘要稳定拒绝。处理、重试、完成、拒绝和死信的时间/错误
  字段组合由数据库约束保护。
- 死信重放要求当前商城 `store.integration-jobs.retry`、对应支付/退款/物流领域权限、五分钟内
  MFA、明确二次确认、原因和 expected version。命令不修改商城、聚合、事件、幂等键或 payload，
  只重置调度字段并写不含 payload 的 append-only 审计。
- handler 按 `event_type + event_version` 注册并检查重复注册。当前只提供支持当前/上一版本的
  `test.reliable-message.probe`；它不调用网络或创建支付/物流事实，且在非 `NODE_ENV=test` 环境
  构造时硬失败。未注册事件按永久失败进入死信，避免静默成功。

## 2. 配置、迁移与回滚

新增配置均有类型、上下限和示例值：

| 配置                                | 默认值 | 约束         |
| ----------------------------------- | ------ | ------------ |
| `OUTBOX_WORKER_INTERVAL_MS`         | 1000   | 1000–300000  |
| `OUTBOX_WORKER_BATCH_SIZE`          | 25     | 1–100        |
| `OUTBOX_WORKER_LEASE_MS`            | 30000  | 5000–300000  |
| `OUTBOX_WORKER_RETRY_BASE_DELAY_MS` | 1000   | 100–300000   |
| `OUTBOX_WORKER_RETRY_MAX_DELAY_MS`  | 300000 | 1000–3600000 |

最大退避不得小于基础退避。worker、日志和数据库领取均保留商城维度；没有新增 Redis/BullMQ 事实源。

`20260725110000_m53_reliable_message_guards` 是第 21 条前向迁移。它不新增表、不启用渠道、不写供应商
或业务成功事实，只加固 M5.2 消息表约束。`down.sql` 检测到任何 outbox/inbox 事实时以 SQLSTATE
`55000` 拒绝；生产或已有事实环境只允许向前修复。当前本地测试库已前滚至 21/21，无 pending。

第一次完整 `verify` 在 lint 阶段发现两处仅类型使用的 import 未使用 `import type`；已做最小修正，
随后从格式检查开始完整重跑并通过。该次失败不计作成功证据。

最终差异审查发现可选 `availableAt` 未传时，重复调用会因两次生成的默认时间不同而误报幂等冲突，
同时 camelCase payload 键未进入 snake_case 敏感词规则。已在不改变迁移和事件契约的前提下仅比较
调用方显式调度时间，并规范化键名后检查 secret/token/PII；新增回归测试。首次定向回归因新增的
到期测试消息未在用例内完成而干扰下一用例，已改为通过真实领取/完成命令收口，最终定向与完整门禁
重新通过；该次测试隔离失败同样不计作成功证据。

M5.3 没有 HTTP 契约、API 或 UI 变化，浏览器 E2E 不适用；未以既有 M4 E2E 冒充消息 worker 验收。
