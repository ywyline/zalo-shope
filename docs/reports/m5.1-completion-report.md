## 2. 官方契约核验与安全决策

| 能力                             | 读取日期/官方版本                   | 冻结结论                                                                                                                              |
| -------------------------------- | ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Zalo Checkout createOrder/method | 2026-07-24；页面最后更新 2026-06-15 | 当前 ZMP SDK 2.51.8 满足 2.45.0 强制 MAC 门槛；ZaloPay code 为 `ZALOPAY_SANDBOX/ZALOPAY`，method 是 `{id,isCustom}` JSON String       |
| Checkout callback/getOrderStatus | 2026-07-24；页面最后更新 2026-06-15 | callback data 使用 Private Key HmacSHA256 校验 `mac/overallMac`；无回调 20 分钟主动查单；金额、method、extradata 和供应商交易均需复核 |
| Checkout refund                  | 2026-07-24；页面最后更新 2026-06-15 | ZaloPay 可请求全额/部分退款；create result 的处理中与 getRefundStatus 最终结果分别映射，未知状态不成功                                |
| GHN v2 API/webhook/status        | 2026-07-24                          | sandbox 使用 dev gateway 和商城独立 Token/ShopId；webhook 文档未声明签名，故只能调度主动 Order Info 查单，不能直接推进状态/金额       |

Zalo Checkout `createOrder` 在 Mini App 内生成 provider order ID。客户端回传该 ID 仅是查单提示；
短期 launch token 和主动查询返回的签名 `extradata` 必须共同绑定商城、会员、内部订单、支付
尝试、金额和 nonce，避免把同商城其他交易错误绑定到当前订单。

## 5. M5.2 门槛与已知限制

- 需要美妆、服装两个商城各自的 Zalo Mini App/Parent App sandbox 配置、Zalo Checkout
  Callback URL/Private Key secret reference、ZaloPay Merchant App 条件/Key 配置和测试成员。
- 需要两个商城各自的 GHN sandbox ShopId、Token secret reference、仓库/退货地址、服务范围、
  COD/面单能力和 webhook 配置。
- 需要可达的 HTTPS callback 域名和批准的密钥管理方案；真实值不得发送到对话、写入 `.env.*`
  示例、测试快照、日志或版本库。
- ZaloPay/GHN sandbox 调用、签名验收、退款、真实运单/面单/轨迹、Zalo 宿主真机和对账均为
  `NOT_RUN/BLOCKED`，不能把纯契约测试表述为真实集成完成。
- GHN webhook 缺少官方签名是当前外部契约限制；M5.2 必须实现 callback-as-hint + active-query，
  不能为开发便利降低为直接信任 Status。

上述限制后由用户批准的受限继续决策替代：允许创建默认无渠道、无业务事实的 M5.2 数据与权限
基础，并继续 M5.3-M5.4 的 test-only 实现；真实适配器、渠道启用和外部验收仍受这些门槛约束。
