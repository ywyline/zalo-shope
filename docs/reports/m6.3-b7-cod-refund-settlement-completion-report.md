## 1. 阶段结论

P0-M6-007 已完成默认关闭的 COD 售后退款结算纵向切片。只有目标商城、目标订单、已签收
`ORDER_OUTBOUND` 运单和订单应收金额均精确匹配的唯一不可变
`COD_REMITTANCE/MATCHED` 对账行，才能证明原 COD 订单已收款并进入售后申请或退款结算。

共享管理员 `/refund` 路由由服务端订单事实选择 ONLINE 或 COD；COD request 只按冻结的
`approved_total_vnd` 创建 `COD_OFFLINE/PENDING` settlement。原 requester 通过独立路由记录规范化转账
观察值，持久化前将引用转为 keyed digest/掩码，将证据转为 digest/密文；另一名具备目标商城直接权限且
近期 MFA 的管理员才能确认。确认事务原子写入 settlement `SUCCEEDED`、
`REFUND_REQUESTED/REFUND_SUCCEEDED`、不可变 confirmation 与审计。

该结论只覆盖 repository implementation + local/test validation。能力开关仍默认 `false`，production
配置和服务层继续拒绝启用。没有执行真实银行转账、退款、provider 调用、sandbox/staging、部署、发布或
rollout，不能据此宣称真实 COD 退款已验收、完整售后已完成或 Production Ready。

## 2. 已实现范围

### 2.1 收款准入与服务端金额

- B3 售后创建和 B7 COD request 只承认唯一精确 `MATCHED` COD 回款行；缺失、差异、重复、跨商城、
  非终态或运单/金额不符均失败关闭。
- 客户端不能提交支付分支、金额、币种、手续费、终态、库存动作或 provider 结果；金额固定为售后审批总额，
  币种固定为 VND。
- COD request 不创建 M5 ONLINE refund、不修改订单/库存/物流、不伪造处理中或成功。

### 2.2 回执与 maker-checker

- 回执入口只允许原 settlement requester，接收严格确认词、expected settlement version、转账时间、引用、
  证据引用和原因；转账时间必须是带时区的 ISO 日期。
- 数据库只保存 keyed transfer/evidence digest、引用掩码、加密证据、服务端身份和时间；公开 settlement
  只投影 `receipt_recorded`，不返回原文或内部 receipt/confirmation 主键。
- 确认入口不接受金额、引用或终态；确认者必须不同于 requester/recorder，并逐字段重验商城、case、订单、
  settlement、金额、VND、回执、版本和 actor。

### 2.3 授权、并发与审计

- request/receipt 要求目标商城直接 `store.after-sales.read` 与
  `store.after-sales.cod-refunds.request`；confirm 要求直接 read 与
  `store.after-sales.cod-refunds.confirm`。权限可由同一商城的多个直接角色聚合，但 cross-access-only 不能
  替代。
- 每条命令在共享 M5 订单退款锁和业务行锁后，以数据库权威时间最终锁定并重验 ACTIVE 商城、管理员、
  session、Bearer、近期 MFA、角色分配和两项直接权限；等待期间撤权或会话失效会在首笔业务写入前失败。
- 商城范围幂等键和规范 request hash 保证同键同参冻结重放、同键异参冲突和并发单胜者；唯一冲突只在回滚
  后以新的 ReadCommitted 事务重验已提交 winner。
- request、receipt、confirm 均记录已验证来源 IP；回执/确认审计使用 SHA-256 身份摘要，不暴露对应内部主键。

## 3. 数据、迁移与回滚

- 第 56 段迁移新增商城隔离、FORCE RLS、append-only 的
  `after_sale_cod_refund_receipts` 与 `after_sale_cod_refund_confirmations`，使用复合外键、唯一索引、最小
  runtime ACL、受限 security-definer 授权函数和 deferred 原子 guard。
- settlement lifecycle guard 允许无完成事实的 `COD_OFFLINE/PENDING`，只有异人确认事务能复制精确回执
  digest/密文并转为 `SUCCEEDED`；ONLINE 行为保持兼容。
- 前向迁移发现任何既有 COD settlement 时以 SQLSTATE `55000` 停止，避免伪造历史回执。down 只允许无
  B7 settlement/receipt/confirmation/audit/transition 事实的 local/test；产生事实后只允许前向修复。
- 应用回滚只关闭新入口并保留已提交资金、时间线和审计事实；不得删除或逆转历史。
