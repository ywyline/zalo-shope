## 1. Delivered

- `ZaloCheckoutPaymentProvider` implements `ZALOPAY_SANDBOX`/`ZALOPAY` createOrder MAC, callback `mac`/`overallMac` verification, getOrderStatus, and normalized `PaymentProviderFact` mapping.
- Provider HTTP calls enforce HTTPS origin allowlist, timeout, response-size/content-type limits, and classified 429/5xx/invalid JSON/retryable errors. Secrets are resolved only through the restricted secret-reference resolver.
- Provider resolution is scoped by store channel, App ID, environment, secret reference, key version, and configuration version. `disabled` never falls back to the test provider; the test provider is test-only.
- Launch responses include a short-lived `launch_token`. Provider-order binding revalidates token/hash, store, and order; binding does not confirm payment success.
- The raw-body webhook resolves one channel by App ID/method before signature verification, validates `extradata`/nonce/amount/order/store, deduplicates callback/inbox messages, and reuses `applyPaymentProviderFact`.
- Callback IP allowlist, rate limiting, IPv4-mapped IPv6 normalization, stale `PROCESSING` lease recovery, and idempotent settle are covered. Failures cannot fabricate payment success.
- A store-scoped `payment.reconcile.requested.v1` is scheduled no later than two minutes after provider acceptance and, when the remaining window is shorter, with a 30-second expiry guard. The worker queries outside database transactions, applies facts only through `applyPaymentProviderFact`, retries pending/transient outcomes through bounded outbox leases, and dead-letters exhausted or review-required outcomes.
- Added the M5.5 migration, OpenAPI/architecture/data-dictionary/roadmap updates, example configuration, and a `55000` rollback guard once callback facts exist.
