## 1. 阶段结论

B5 已完成默认关闭的会员返件登记、受审管理员可信人工物流事实和 B1 待验收读取复用。会员只可在
排他寄回截止点前创建唯一 `SUBMITTED` 返件并追加 `START_RETURN`；会员填写的承运商和运单号不是
可信在途/送达事实。管理员只能在目标商城直接 review 权限、近期 MFA、确认词、原因和 aggregate/返件
双版本约束下记录 `IN_TRANSIT` 或 `DELIVERED`。直接送达在同一事务补齐
`RETURN_SHIPPED`/`RETURN_RECEIVED`，最终 `INSPECTION_PENDING` 只表示等待验收，不表示验收完成。

运单号只以 `PII_HASH_KEY` keyed HMAC 和掩码持久化；明文不进入数据库、operation 结果、审计、日志、
公开响应或错误。两条命令均使用商城隔离的安全定义函数、Serializable 有界重试、幂等 request hash、
最终授权重验和 operation/transition/audit deferred 原子 guard。

该结论只将 **B5 default-disabled repository implementation + local/test validation** 标记为
`COMPLETE`。`AFTER_SALE_RETURN_COMMANDS_ENABLED` 默认 `false`，production 配置和 service 均拒绝启用。
真实物流供应商、验收写入、库存恢复、退款/COD、换货履约、UI、部署和 rollout 均为
`NOT_AUTHORIZED / NOT_RUN`；B2/B2b、B6-B7、M6.3、M6 与 P0 继续未完成。

## 2. 已实现范围

### 2.1 API、隐私与授权

- 注册会员 `POST /v1/after-sales/{afterSaleId}/return-shipment` 与管理员
  `POST /v1/admin/after-sales/{afterSaleId}/return-shipment/fact`；严格绑定 Store-Code、认证主体、目标 case、
  Idempotency-Key、来源 IP 和服务端 correlation ID。
- 会员路由只接受承运商、运单号和 expected aggregate version。输入 NFKC 规范化并拒绝 C0/DEL 控制字符；
  HMAC key 少于 32 字符失败关闭，原始运单号只在请求内存中用于摘要和掩码。
- 管理员路由只接受 `IN_TRANSIT/DELIVERED`、确认词、至少 10 字符原因、expected aggregate version 与
  expected return-shipment version；要求目标商城直接 `store.after-sales.review` 和近期 MFA。
  `platform.stores.cross_access` 不能替代直接权限。
- 成功与幂等重放只返回冻结的 operation acknowledgement。B1 列表/详情继续使用严格 projector，只暴露
  掩码、可信返件状态、版本和时间线；响应保持 correlation/no-store 头。

### 2.2 状态、截止与原子性

- 会员登记只允许 `APPROVED RETURN_REFUND/EXCHANGE`、正数批准权益、至少一个批准行且尚无返件的 case；
  创建 `SUBMITTED` 后只追加 `START_RETURN: APPROVED -> RETURN_PENDING`。
- 排他截止点优先于 expected-version 检查。到期 worker 先提交时，会员命令稳定返回
  `AFTER_SALE_RETURN_WINDOW_CLOSED`，不会被随后递增的聚合版本遮蔽；提交与到期至多一个成功。
- 管理员 `IN_TRANSIT` 只从 `RETURN_PENDING + SUBMITTED` 推进到
  `RETURN_IN_TRANSIT + IN_TRANSIT`。`DELIVERED` 可从该状态追加一次 `RETURN_RECEIVED`，也可从
  `RETURN_PENDING + SUBMITTED` 原子补 `RETURN_SHIPPED` 后再追加 `RETURN_RECEIVED`。
- 可信管理员事实不再错误复用会员登记截止点；它只协调已经按时提交的返件，不能创建新返件，也不触发
  inspection、库存、退款、COD、换货或外部物流副作用。
- 幂等 advisory lock 后统一使用订单 advisory lock、订单行锁、售后聚合和返件锁序。明确 expected-version
  冲突不重试；仅 Prisma `P2034`/SQLSTATE `40001` serialization 最多重试三次。

### 2.3 数据库边界与迁移

- 第 52 段 `20260731150000_m63_b5_after_sale_return_trust` 扩展 B3/B4 operation allowlist、link/completion
  guard 和 deferred operation/transition/audit 原子 guard，并增加两条窄 security-definer 命令。
- runtime 对 `after_sale_return_shipments` 的直接 `INSERT/UPDATE` 已撤销；会员/管理员都不能绕过命令写
  `SUBMITTED/IN_TRANSIT/DELIVERED`。B5 专用管理员 transition guard 只允许受审函数内的两类事件。
- 所有读取、写入、唯一性、复合关系、权限重验、operation 和审计都包含 `store_id`。管理员跨商城写
  保持关闭，会员只能登记本人、当前商城售后单。
- `down.sql` 仅允许无 B5 operation、可信返件状态、B5 transition/audit 的 local/test scratch；存在事实
  时以 SQLSTATE `55000` 停止。production 或已有 B5 事实环境只允许经审查的前向修复。

## 5. 已知限制与生产阻断项

1. **没有真实物流 provider**：管理员事实来自受审人工核验，不是 GHN/GHTK 查询或 callback；当前不能
   宣称真实承运商状态已集成。
2. **待验收不等于验收**：没有 inspection 写路由、仓库质检结论或 exactly-once 库存恢复；
   `INSPECTION_PENDING` 只表示返件已可信送达并等待后续处理。
3. **没有资金或换货履约**：B5 不创建 M5 refund、COD settlement、replacement reservation、
   `EXCHANGE_OUTBOUND` 或任何供应商 outbox。B6/B7 与完整验收/库存仍需独立计划和授权。
4. **生产政策与合规未批准**：退货期限、运费承担、人工物流核验规则和越南合规仍需业务、隐私与合规
   审批；local/test fixture 不是法律意见或生产配置。
5. **无专项 UI/E2E 和完整 OpenAPI 语义校验**：没有三语移动端、管理工作台或 Zalo 真机验收；本地
   引用检查不能替代 OpenAPI 3.1 专用语义 linter。
6. **依赖公告仍开放**：生产依赖 high 门禁通过，但 3 项 React Router moderate 公告仍需后续依赖治理。
